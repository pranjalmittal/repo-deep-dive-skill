## Cross-language grep recipes

Use the Grep tool (or `rg`) with these patterns, excluding vendored and build dirs.

| Looking for | Pattern(s) |
|---|---|
| Env vars read | `os\.environ\|os\.getenv\|process\.env\.\|System\.getenv\|ENV\[\|env::var\|os\.Getenv\|getenv\(` |
| HTTP routes | `@(app\|router\|bp)\.(get\|post\|put\|delete\|route)\|@(Get\|Post\|Put\|Delete\|Request)Mapping\|router\.(get\|post)\|\.HandleFunc\(\|resources? :` |
| Background jobs / queues | `celery\|@task\|bull\|Queue\(\|sidekiq\|perform_async\|kafka\|sqs\|pubsub\|rabbit\|@Scheduled\|cron` |
| DB access | `SELECT \|INSERT \|session\.query\|\.objects\.\|prisma\.\|knex\|TypeORM\|@Entity\|gorm\|sqlx\|ActiveRecord` |
| Outbound HTTP / integrations | `requests\.\|httpx\|fetch\(\|axios\|http\.Client\|RestTemplate\|WebClient\|Faraday\|reqwest` |
| Feature flags | `feature_flag\|isEnabled\|launchdarkly\|unleash\|flipper\|growthbook` |
| Auth | `jwt\|oauth\|session\|authenticate\|authorize\|@login_required\|passport\|middleware` |
| Generated code markers | `DO NOT EDIT\|@generated\|auto-generated\|Code generated by` |

## Python

- **Packaging / entry**: `pyproject.toml` (`[project.scripts]` = CLI entry points), `setup.py`/`setup.cfg`, `__main__.py`, `src/<pkg>/` vs flat layout.
- **Django**: `manage.py` → `settings.py` (`INSTALLED_APPS`, `MIDDLEWARE`, `DATABASES`) → root `urls.py` → per-app `urls.py` / `views.py` / `models.py` / `admin.py` / `signals.py`; migrations in `<app>/migrations/`; Celery in `celery.py` + `tasks.py`.
- **Flask**: app factory `create_app()` in `__init__.py` or `app.py`; blueprints registered via `register_blueprint`; extensions initialised with `init_app`.
- **FastAPI**: `FastAPI()` instance, `include_router(...)`, dependencies via `Depends(...)` (the DI graph is the architecture); Pydantic models = API contracts.
- **Data**: SQLAlchemy models + `alembic/versions/`; Pydantic schemas; `dataclasses`.
- **Tests**: `tests/` + `conftest.py` (fixtures are the setup story); `pytest.ini` / `[tool.pytest.ini_options]`; `tox.ini` / `noxfile.py`.
- **Config**: `settings.py`, `config.py`, pydantic `BaseSettings`, `.env` via `python-dotenv`.

## JavaScript / TypeScript

- **Entry**: `package.json` `main`/`module`/`exports`/`bin` and the `scripts.start` / `scripts.dev` commands; `src/index.ts`, `server.ts`, `app.ts`.
- **Express / Fastify / Koa**: app creation → `app.use(...)` middleware order (auth, parsing, error handler last) → routers.
- **NestJS**: `main.ts` → `AppModule`; `*.module.ts` define the dependency graph; `*.controller.ts` (routes), `*.service.ts` (logic), guards/interceptors/pipes = cross-cutting.
- **Next.js**: `app/` (App Router: `page.tsx`, `layout.tsx`, `route.ts`, server actions) or `pages/` (+ `pages/api/`); `middleware.ts`; `next.config.*`.
- **React SPA**: `main.tsx`/`index.tsx` → router config → state management (Redux slices, Zustand stores, React Query hooks); API client module.
- **Data**: Prisma `schema.prisma`, TypeORM entities, Drizzle schema, Mongoose models, Knex migrations.
- **Tests**: Jest/Vitest config, `*.test.ts`, `__tests__/`; Playwright/Cypress for e2e.
- **Config**: `tsconfig.json` `paths` aliases (needed to resolve imports), `.env*`, `config/`.

## Go

- **Entry**: `cmd/<binary>/main.go` (one per binary); `main.go` at root for single-binary repos.
- **Layout**: `internal/` (private packages, usually the core), `pkg/` (public), `api/` (OpenAPI/proto).
- **HTTP**: `net/http` `HandleFunc`, chi/gin/echo routers; gRPC: `.proto` files + generated `*.pb.go` (don't edit).
- **Wiring**: usually explicit in `main.go` (constructors passed down); look for `wire.go` (Google Wire) or fx.
- **Tests**: `*_test.go` next to code; `testdata/`; table-driven tests.

## Java / Kotlin

- **Spring Boot**: `@SpringBootApplication` class → `@RestController`/`@Controller` → `@Service` → `@Repository`/JPA `@Entity`; config in `application.yml`/`application.properties` + profiles (`application-<env>.yml`); `@Configuration` beans; `@Scheduled`, `@KafkaListener`.
- **Build**: `pom.xml` modules or `settings.gradle` `include(...)` show the module graph.
- **Layout**: `src/main/java|kotlin`, `src/main/resources`, `src/test/...`; DB migrations in `resources/db/migration` (Flyway) or Liquibase changelogs.
- **Android**: `AndroidManifest.xml` (activities, services, permissions), `Application` subclass, navigation graphs, Hilt/Dagger modules.

## Ruby (Rails)

- `config/routes.rb` → `app/controllers` → `app/models` (ActiveRecord; callbacks and concerns hide a lot) → `app/services` / `app/jobs` (Sidekiq/ActiveJob); `db/schema.rb` is the fastest read of the data model; `config/initializers/` for integrations; `Gemfile` for capabilities. Tests in `spec/` (RSpec) or `test/` (Minitest).

## Rust

- `Cargo.toml` `[workspace] members` = crate graph; `src/main.rs` (binary) / `src/lib.rs` (library); `[[bin]]` entries; `mod` declarations map files to modules; feature flags in `[features]` change what compiles; `build.rs` = build-time codegen; tests inline (`#[cfg(test)]`) and in `tests/`.

## PHP

- **Laravel**: `routes/web.php`, `routes/api.php` → `app/Http/Controllers` → `app/Models`; `app/Providers` (service container bindings); `database/migrations`; `config/*.php`; queues in `app/Jobs`.
- **Symfony**: `config/routes.yaml` or attribute routes, `src/Controller`, `config/services.yaml`.

## C# / .NET

- `*.sln` → `*.csproj` projects (references = dependency graph); `Program.cs` (minimal hosting: service registration + middleware pipeline); controllers or minimal-API `MapGet`; EF Core `DbContext` + `Migrations/`; `appsettings*.json`.

## Mobile

- **iOS**: `*.xcodeproj`/`*.xcworkspace`, `Package.swift`/`Podfile`; `@main` App struct or `AppDelegate`; SwiftUI views vs UIKit view controllers; networking layer; `Info.plist`.
- **Flutter**: `pubspec.yaml`, `lib/main.dart`, routing (go_router), state (Bloc/Riverpod/Provider).

## Infrastructure-as-code and deployment

- **Docker**: `Dockerfile` (`CMD`/`ENTRYPOINT` = what actually runs in prod), `docker-compose*.yml` (local topology and dependent services — often the best runtime-architecture diagram in the repo).
- **Kubernetes / Helm**: `Chart.yaml`, `values*.yaml` (per-env config), `templates/`; Kustomize overlays.
- **Terraform**: `main.tf`, `variables.tf`, `modules/`, per-env dirs or workspaces; state backend config.
- **CI/CD**: `.github/workflows/*.yml` (triggers, jobs, required checks, deploy steps), `.gitlab-ci.yml`, `Jenkinsfile`. CI files show the *real* build and test commands.

## Monorepos

- Find the workspace definition first: `pnpm-workspace.yaml`, `package.json` `workspaces`, `nx.json`/`project.json`, `turbo.json`, `lerna.json`, Cargo `[workspace]`, `go.work`, Gradle `settings.gradle`, Bazel `BUILD` files, Maven `<modules>`.
- Build a package/service table: name, path, kind (app/lib/tool), purpose, depends-on.
- Identify the 1–3 packages everything depends on (shared core) and the deployable apps at the edges.
- Check how shared code is versioned (workspace protocol, internal publishing) and how CI decides what to build (affected-graph tooling, path filters).
